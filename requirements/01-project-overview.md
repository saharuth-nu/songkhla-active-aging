# Project Overview

## ข้อมูลโครงการ

| รายการ | รายละเอียด |
|--------|-----------|
| **ชื่อโครงการ** | Songkhla Active Aging Model: นวัตกรรมกระบวนการมีส่วนร่วมเพื่อสร้างสุขภาวะและเศรษฐกิจสุขภาพผู้สูงอายุอย่างยั่งยืน |
| **ชื่อระบบ** | Songkhla Active Aging Digital Platform |
| **ระดับการพัฒนา** | Minimum Viable Platform (MVP) |
| **ผู้ว่าจ้าง** | มหาวิทยาลัยสงขลานครินทร์ (PSU) |
| **วงเงิน** | ไม่เกิน 70,000 บาท |
| **Domain / URL** | ⚠️ รอผู้ว่าจ้างยืนยัน |
| **ภาษาของระบบ** | ภาษาไทย ⚠️ รอยืนยันว่ามีภาษาอังกฤษด้วยหรือไม่ |

## วัตถุประสงค์ของระบบ

1. รวบรวมและบริหารจัดการข้อมูลผู้รับบริการ ผลิตภัณฑ์/บริการ กิจกรรม การพัฒนาศักยภาพ การถ่ายทอดเทคโนโลยี การจ้างงาน เครือข่าย และผลลัพธ์ของโครงการในฐานข้อมูลกลาง
2. เป็นช่องทางประชาสัมพันธ์ เผยแพร่องค์ความรู้ แสดงผลิตภัณฑ์/บริการ และรับคำขอซื้อ/ขอรับบริการจากผู้ใช้งาน
3. บันทึกและติดตาม Order/Request/Transaction พร้อมสถานะ
4. แสดง Dashboard KPI ผลผลิต ผลลัพธ์ และข้อมูลทางธุรกิจของโครงการแบบ Real-time
5. เชื่อมโยงการสื่อสารจาก Facebook, Hatyai Connext, QR Code และกิจกรรมภาคสนามเข้าสู่แพลตฟอร์มผ่าน UTM/Campaign Tracking
6. ให้ทีมโครงการบริหารข้อมูลได้เองโดยไม่ต้องแก้ Source Code
7. ส่งมอบระบบให้กลไกวิสาหกิจเพื่อสังคมหรือหน่วยงานในพื้นที่ดำเนินการต่อในระยะต่อไปได้

## กลุ่มผู้ใช้งานและสิทธิ์

| กลุ่ม | สิทธิ์การใช้งาน |
|-------|--------------|
| **ประชาชนทั่วไป** | อ่านข้อมูลสาธารณะ, ดูผลิตภัณฑ์/บริการ, อ่านข่าว/องค์ความรู้ |
| **ผู้สูงอายุ/ผู้รับบริการ/ผู้ดูแล** | ลงทะเบียน, ส่งคำขอรับบริการ/สั่งซื้อ, ติดตามสถานะคำขอด้วย Request Code |
| **ผู้ประกอบการ/บุคลากร/ภาคี** | ลงทะเบียนผ่านแบบฟอร์มที่กำหนด หรือผ่าน Admin |
| **Project Admin** | จัดการข้อมูลทุกหมวด, Import/Export, จัดการ KPI, จัดการผู้ใช้ |
| **Viewer / Executive** | ดู Dashboard และรายงานสรุปอย่างเดียว ไม่มีสิทธิ์แก้ไขข้อมูล |

## ขอบเขตที่ไม่รวมใน MVP

- Native Mobile Application (iOS / Android)
- Payment Gateway เต็มรูปแบบ
- ระบบบัญชี / ภาษี / คลังสินค้า / โลจิสติกส์
- ERP / CRM เต็มรูปแบบ
- การเชื่อมต่อ API กับ HIS / HDC หรือระบบภายนอกที่ซับซ้อน
- AI / Advanced Analytics
- High Availability / Load Balancing / Auto Scaling
- Feature หรือ Business Process ใหม่ที่ไม่ได้ระบุใน TOR

## รายการที่รอการยืนยันจากผู้ว่าจ้าง

| # | คำถาม | ผลกระทบถ้าไม่ยืนยัน |
|---|-------|-------------------|
| 1 | **Domain / URL จริงที่จะใช้คืออะไร?** | ไม่สามารถระบุใน Config และเอกสารได้ |
| 2 | **ระบบรองรับภาษาอังกฤษด้วยหรือไม่?** | กระทบ UI และโครงสร้างข้อมูล |
| 3 | **ข้อความ PDPA Consent ที่ใช้ในแบบฟอร์มคืออะไร?** | ไม่สามารถสร้างแบบฟอร์มสมบูรณ์ได้ |
| 4 | **มีโลโก้ / สีองค์กร / Brand Guideline แล้วหรือไม่?** | กระทบการออกแบบ UI ทั้งระบบ |
| 5 | **แบบฟอร์มลงทะเบียนผู้ประกอบการ/บุคลากร/ภาคี ต้องการฟิลด์อะไรบ้าง?** | ไม่สามารถสร้างแบบฟอร์มได้ถูกต้อง |
| 6 | **ช่องทางชำระเงินที่ต้องการรองรับมีอะไรบ้าง?** เช่น โอนเงิน, QR Code พร้อมเพย์ | กระทบ Flow การแนบหลักฐานใน Marketplace |
| 7 | **การอบรมต้องการแบบ Onsite หรือ Online และมีกำหนดการวันไหน?** | ต้องวางแผนร่วมกันก่อนงวดที่ 3 |
